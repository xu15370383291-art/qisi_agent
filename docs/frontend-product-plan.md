# 启思学伴前端产品与视觉重构规划

> 适用范围：学生端、教师端、系统管理端  
> 规划目标：在保留现有后端能力的基础上，把当前“功能演示页”升级为结构清晰、可持续迭代、具有教育产品辨识度的正式前端。

## 1. 规划结论

当前项目并不是缺少功能，而是存在四个更核心的问题：

1. **角色和场景混在一起**：学生、教师功能共用一个超长单页，登录后主要依赖隐藏节点区分权限，导航和页面心智不够清晰。
2. **学习闭环不够突出**：问答、练习、错题、画像已经存在，但它们更像五个独立页面，没有形成“学习目标 → 理解 → 练习 → 纠错 → 复习”的连续体验。
3. **数据展示多、行动指引少**：首页有多个统计数字，但缺少“今天应该先做什么”“为什么推荐这一步”“做完后发生什么”的行动链路。
4. **前端工程难以继续扩展**：目前使用单体 HTML、超长 JavaScript 和单个 CSS 文件，路由、状态、组件、权限、错误处理和测试都不利于长期维护。

建议采用以下总方向：

```text
学生端：围绕“今天学什么、哪里不会、下一步做什么”组织
教师端：围绕“谁需要关注、为什么、现在如何干预”组织
管理端：围绕“账号、内容、任务、质量、风险”组织
```

第一期不建议继续在当前页面上零散加卡片，而应先完成信息架构和技术底座重构，再逐步补充高级功能。

## 2. 当前能力盘点

### 2.1 已有前端功能

- 学生/教师注册、登录、身份识别、退出登录。
- 学生学习总览、学习对话、历史会话、练习、错题、学习画像。
- SSE 流式回答、教材引用、停止生成、重新生成、复制和本地回答反馈。
- 按年级、难度和知识点生成练习，保存未提交草稿并展示练习结果。
- 错题筛选、搜索、标记已复习和跳转专项练习。
- 教师查看学生列表、学习线索、待审核记忆、学生详情和检索调试。
- 管理员查看系统概览、用户、错题、提问记录，以及上传教材和题库。

### 2.2 已有后端接口可直接支撑的功能

| 领域 | 现有能力 | 前端可以立即完善的部分 |
|---|---|---|
| 鉴权 | 注册、登录、当前用户、角色权限 | 独立角色入口、登录态恢复、403/失效态、首次使用引导 |
| 会话 | 创建、列表、读取、删除、SSE 对话 | 会话管理器、删除确认、空状态、断线恢复提示、过程状态展示 |
| 练习 | 分类、生成、提交、评分 | 答题导航、结果复盘、错题回练、草稿恢复、提交确认 |
| 错题 | 列表、状态更新 | 多维筛选、详情抽屉、专项练习入口、复习完成反馈 |
| 学习画像 | 掌握度、学习事件、记忆 | 知识点分组、薄弱项排序、解释指标、推荐下一步 |
| 教师 | 班级摘要、学生详情、记忆审核 | 风险队列、学生侧栏、知识点筛选、审核工作台 |
| 管理员 | 概览、用户、活动、内容上传、任务查询 | 完整表格体验、导入任务进度、错误态、批量筛选与导出 |

### 2.3 当前前端主要缺口

- 没有真正的 URL 路由，刷新、返回、深链接和页面级权限体验较弱。
- 学生和教师共享同一套导航，页面职责边界不够清晰。
- 会话、练习和教师详情大量依赖动态拼接 `innerHTML`，维护风险高。
- 页面状态分散在全局对象和 DOM 中，数据请求没有统一缓存、重试和错误规范。
- CSS 单文件持续追加，设计变量、组件样式和页面样式没有分层。
- 移动端只是压缩桌面布局，底部导航、触控目标和长列表体验不足。
- 使用外部 Google Fonts，在国内网络环境下可能加载失败。
- 缺少页面级 loading、skeleton、error boundary、离线/弱网状态和统一确认弹窗。
- 缺少前端单元测试、组件测试、关键流程 E2E 和可访问性验收。

## 3. 产品定位与核心体验

### 3.1 具体用户

- **主要用户**：七至九年级学生，需要快速弄懂数学问题并形成持续复习习惯。
- **协同用户**：数学教师，需要用有限时间定位值得优先关注的学生和知识点。
- **运营用户**：系统管理员，需要保证账号、教材、题库和知识服务稳定可用。

### 3.2 学生端唯一核心任务

让学生每次进入系统都能回答三个问题：

1. 我今天先学什么？
2. 我具体卡在哪里？
3. 完成这一步后，下一步是什么？

### 3.3 学习闭环

```text
今日任务
  ↓
AI 讲解与教材依据
  ↓
随堂小练 / 专项练习
  ↓
错因与薄弱知识点
  ↓
错题复习与再次验证
  ↓
掌握度更新和下一步建议
```

所有学生端页面都应至少提供一个回到这条闭环的明确行动，不做没有下一步的“纯数据陈列页”。

## 4. 新信息架构

### 4.1 学生端

```text
/student
├─ /home                 今日学习
├─ /chat                 AI 学伴
│  └─ /chat/:sessionId   指定学习会话
├─ /practice             练习中心
│  ├─ /practice/setup    组卷设置
│  ├─ /practice/:quizId  作答页
│  └─ /practice/:quizId/result  结果复盘
├─ /mistakes             错题本
│  └─ /mistakes/:id      错题详情
├─ /growth               学习成长
└─ /settings             账号与偏好
```

桌面端使用左侧主导航，移动端使用 5 项底部导航：“今日、学伴、练习、错题、我的”。历史会话只在“AI 学伴”内部出现，不再常驻整个应用侧栏。

### 4.2 教师端

```text
/teacher
├─ /overview             教学概览
├─ /students             学生学情
│  └─ /students/:id      学生详情
├─ /knowledge            知识点学情
├─ /review               AI 学习线索审核
├─ /activity             提问与错题动态
└─ /settings             个人设置
```

“检索调试”属于系统诊断，不应放在教师主要教学路径中。建议迁到管理员端“质量监控”，或只对具备高级权限的教师显示。

### 4.3 管理端

```text
/admin
├─ /overview             系统概览
├─ /users                用户与权限
├─ /content              教材与题库
│  ├─ /content/documents 文档列表
│  ├─ /content/imports   导入任务
│  └─ /content/:id       文档详情与版本
├─ /activity/questions   提问记录
├─ /activity/mistakes    错题记录
├─ /quality/retrieval    检索质量
├─ /quality/errors       异常与失败任务
└─ /settings             系统设置
```

## 5. 学生端完整功能规划

### 5.1 登录与首次使用

#### P0：现有接口可完成

- 登录和注册拆成清晰的两个状态，不在登录时要求再次选择账号角色。
- 登录页提供“学生登录”“教师登录”“管理员入口”的清晰分流。
- 表单支持密码显隐、Caps Lock 提醒、加载状态、字段级错误和错误后自动聚焦。
- 登录失效后保留原访问地址，重新登录后回到原页面。
- 首次登录引导选择当前年级，并说明数据将如何用于个性化学习。

#### P1：需要新增接口

- 忘记密码、修改密码、绑定手机号/邮箱。
- 年级、学习目标、每日学习时长和提醒偏好的持久化。
- 未成年人隐私授权或监护人确认流程。

### 5.2 今日学习首页

首页不再以四个统计数字作为主体，而以“今日行动”作为第一视觉焦点。

#### 核心模块

1. **今日主任务**：根据待复习错题和最低掌握度，给出一个可直接开始的任务。
2. **继续上次学习**：恢复最近会话或未完成练习。
3. **复习队列**：显示今天建议处理的 3 个知识点或错题。
4. **本周学习节奏**：展示近 7 天对话、练习和复习完成情况。
5. **掌握度变化**：只展示变化最大的知识点，并说明变化原因。
6. **最近成果**：例如“完成一元一次方程专项，正确率从 60% 提升到 80%”。

#### P0 数据策略

先使用现有画像、错题和会话数据生成首页推荐；数据不足时明确展示“完成一组练习后生成计划”，避免伪造趋势。

#### P1 后端增强

- 今日任务和推荐理由接口。
- 学习天数、周趋势、练习历史和最近未完成任务接口。
- 首页模块排序与个性化配置。

### 5.3 AI 学伴

#### 会话列表

- 新建对话、搜索会话、按日期分组、删除确认、空状态。
- 会话标题优先显示首个问题摘要；P1 增加重命名和自动标题接口。
- 切换会话时保留滚动位置和草稿。

#### 对话区

- 显示“理解问题 → 查找教材 → 组织讲解”的阶段状态，充分利用现有 SSE 事件。
- 回答采用教育结构：结论、分步讲解、关键提醒、教材依据、建议练习。
- 引用以可展开的来源卡展示：教材、章节、片段、相关度。
- 支持停止生成、重试、复制、赞踩、跳转专项练习。
- 对“知识库外”问题使用明确边界提示，并给出可继续询问的方向。
- 网络中断时保留学生问题，提供“一键重试”。
- 输入框支持常用提问模板：“讲概念”“分析错因”“一步一步提示”“出一道类似题”。

#### P1 增强

- 图片题目上传、OCR 预览、裁剪和旋转。
- 回答反馈写入后端，而不是只存在本地存储。
- 消息编辑后重新提问、会话重命名、引用详情页。
- 教学模式选择：直接讲解、苏格拉底式提示、只给下一步提示。

### 5.4 练习中心

#### 练习设置

- 选择年级、知识点、难度、题量和练习来源。
- 提供“智能推荐”“错题巩固”“章节练习”三个快速入口。
- 组卷前显示预计时长和覆盖知识点。

#### 作答页

- 单题聚焦模式，顶部显示进度，侧边/底部提供题号导航。
- 自动保存草稿，离开时对未提交答案进行确认。
- 标记不确定、暂时跳过、键盘快捷操作。
- 不在作答过程中直接泄露正确答案。
- 移动端固定底部“上一题 / 下一题 / 提交”。

#### 结果复盘

- 总分、正确率、用时、知识点表现。
- 每题展示：我的答案、正确答案、解析、教材来源和错因标签。
- 一键“只练错题”“继续同知识点”“去问 AI”。
- 明确说明掌握度为何发生变化。

#### P1 增强

- 练习历史、计时、收藏题、主观题、作业模式。
- 题目反馈：题干错误、答案争议、解析看不懂。
- 自适应难度和基于错因的下一题推荐。

### 5.5 错题本

#### P0

- 按待复习、已复习、知识点、日期和关键词筛选。
- 列表卡片显示题目摘要、错因、知识点、状态和最近复习时间。
- 错题详情显示完整题目、我的答案、正确答案、解析和来源。
- 提供“专项练习”“问 AI”“标记已复习”三个主操作。
- 批量选择错题生成一组复习练习。

#### P1

- 复习状态从二态升级为：待复习 → 复习中 → 已掌握。
- 学生错题笔记、同类题、复习计划和间隔重复提醒。
- 支持手动录入或拍照加入错题本。
- 错因标签：概念不清、计算错误、审题错误、方法选择错误。

### 5.6 学习成长

将当前“我的画像”改为学生更容易理解的“学习成长”。

#### 核心模块

- 掌握度概览：按章节分组，而不是平铺所有知识点。
- 薄弱知识点：展示当前分数、证据和建议动作。
- 进步记录：显示真实可验证的变化，不使用无来源的激励文案。
- 学习事件时间线：对话、练习、错题复习合并展示。
- 学习建议：最多三条，按优先级排列，每条都可直接执行。
- 数据说明：解释掌握度如何计算、最后更新时间和数据不足状态。

#### P1

- 周报/月报、目标设置、学习时长、正确率趋势、成就系统。
- 学生可以对不准确的画像提出更正或隐藏某条学习记忆。

### 5.7 设置与帮助

- 个人资料、年级、默认学科、字体大小和减少动画。
- 账号安全、退出登录、数据与隐私说明。
- 产品帮助、问题反馈、服务状态。
- P1 增加导出学习数据和删除账号申请。

## 6. 教师端完整功能规划

### 6.1 教学概览

- 今日需要关注的学生，不以总人数作为第一信息。
- 待审核学习线索、集中薄弱知识点、近期高频提问、未处理错题。
- 每个风险提示必须带“依据”和“查看学生/知识点”入口。
- 数据不足时显示采集条件，而不是空白图表。

### 6.2 学生学情

- 学生列表支持搜索、风险筛选、知识点筛选和排序。
- 列表显示最近学习、薄弱点、待处理数和最后活跃时间。
- 学生详情包含：掌握度、错题、最近会话摘要、学习事件和教师备注。
- 教师可从薄弱知识点直接生成跟进建议或专项练习。

### 6.3 知识点学情

- 按章节展示班级知识点掌握分布。
- 点开知识点后显示受影响学生、典型错题和高频提问。
- 只在有足够数据时展示趋势和对比，避免误导性图表。

### 6.4 AI 学习线索审核

- 将待审核记忆从学生列表中抽离成独立工作台。
- 支持确认、修正、删除、查看来源对话和批量处理。
- 显示 AI 置信度、生成时间、学生和知识点。
- 所有修改保留操作结果反馈；P1 增加审核历史和撤销。

### 6.5 教学活动

- 合并查看学生提问、错题和练习表现。
- 支持按学生、知识点、时间和类型筛选。
- 可导出当前筛选结果。

### 6.6 P1/P2 教师能力

- 班级与学生分组。
- 发布练习/作业、查看完成情况、催办。
- 教师备注、关注学生、干预记录。
- 班级周报和知识点对比。
- 教师对 AI 回答和知识内容的纠错反馈。

## 7. 管理端完整功能规划

### 7.1 系统概览

- 账号状态、内容状态、导入任务、失败任务和最近异常。
- 明确展示数据更新时间和服务状态来源。
- 将“需要处理的事项”放在统计卡之前。

### 7.2 用户与权限

- 搜索、角色、状态、注册时间筛选。
- 用户详情抽屉：基本信息、最近活动、账号状态。
- 停用账号必须二次确认并说明影响。
- P1 增加重置密码、批量导入、批量停用和操作审计。

### 7.3 教材与题库

- 文档列表：名称、年级、类型、状态、版本、上传者、更新时间。
- 上传流程：文件校验 → 元数据确认 → 上传 → 处理进度 → 结果。
- 导入任务显示阶段、百分比、耗时和失败原因，并轮询现有任务接口。
- 文件格式、大小和年级错误在上传前反馈。
- P1 增加版本管理、重新处理、停用/删除、内容预览和知识点映射。

### 7.4 学习活动

- 提问和错题使用统一的活动查询布局。
- 支持关键词、学生、知识点、状态和时间范围筛选。
- 详情中展示来源、关联会话和必要的脱敏信息。

### 7.5 质量监控

- 将检索调试从教师端迁入此处。
- 展示检索候选、分数、章节、模型、查询条件和响应耗时。
- P1 增加低评分回答、用户负反馈、无结果查询和失败任务列表。
- P2 增加评测集运行和版本对比。

## 8. 全局体验规范

### 8.1 必须统一的页面状态

每个数据模块都需要定义以下状态：

- 首次进入的 skeleton。
- 正常数据。
- 无数据且可行动的空状态。
- 请求失败及重试。
- 无权限。
- 登录失效。
- 弱网/离线。
- 操作进行中和操作完成反馈。

### 8.2 权限与导航

- 路由守卫按 `student / teacher / admin` 控制页面访问。
- 无权限页面跳转到对应首页，并明确说明原因。
- 不仅隐藏按钮，服务端权限错误也要有统一处理。
- 学生端、教师端和管理端使用不同应用壳，避免角色功能互相干扰。

### 8.3 可访问性

- 所有图标使用统一 SVG 图标库，不再依赖含义不明确的 Unicode 符号。
- 键盘可完成主要操作；焦点样式必须清晰可见。
- 颜色不是状态的唯一表达，状态同时有文本或图形。
- 文本与背景满足 WCAG AA 对比度。
- 支持 `prefers-reduced-motion`、字体缩放和触控目标最小尺寸。

### 8.4 内容语言

- 面向学生使用短句和主动语态，例如“开始练习”“查看解析”“继续复习”。
- 不使用含义模糊的词，如“学习信号”“线索积累中”，除非旁边解释具体含义。
- 错误文案同时说明发生了什么和接下来怎么办。
- 相同动作在按钮、加载提示和成功提示中使用同一个名称。

## 9. 视觉设计方向

### 9.1 设计概念：解题轨迹纸

视觉不采用通用 SaaS 仪表盘，也不做低龄卡通。设计语言来自学生真实使用的方格草稿纸、批注、步骤线和教材页签：克制、清晰，但保留“正在推理”的感觉。

唯一需要大胆使用的标志性元素是 **“学习路径尺”**：一条贯穿关键页面的纵向步骤轨迹，显示“理解 → 练习 → 订正 → 掌握”的当前位置。其他装饰保持安静，避免全页面都出现渐变、漂浮光斑或无意义数字编号。

### 9.2 色彩令牌

| 名称 | 色值 | 用途 |
|---|---|---|
| 墨蓝 `Ink` | `#17324D` | 主文字、导航和稳定感 |
| 纸白 `Paper` | `#F7F9F8` | 页面背景，不使用偏黄模板色 |
| 粉笔青 `Chalk Teal` | `#1F8A83` | 主操作、掌握和链接 |
| 批注朱 `Mark Red` | `#D95C4B` | 错误、待处理和教师批注 |
| 铅笔黄 `Pencil` | `#E6B84A` | 提示、进行中和关键步骤 |
| 图纸蓝 `Blueprint` | `#4E73A8` | 引用、信息和知识来源 |

颜色使用规则：主页面最多同时出现一个主色和一个状态色，不能把六种颜色平均分配给所有卡片。

### 9.3 字体系统

- 中文展示字体：自托管 `LXGW WenKai Screen`，仅用于学生端短标题、关键问题和步骤名称。
- 正文与界面字体：自托管 `MiSans` 或 `Noto Sans SC`。
- 数据与来源编号：`JetBrains Mono`。
- 教师和管理端大面积表格不使用手写体。
- 不再依赖 Google Fonts 在线加载。

### 9.4 布局原则

- 学生端内容最大宽度约 1200px，对话正文控制在适合阅读的行宽。
- 卡片不是默认容器；只有需要独立操作、状态或分组的内容才使用卡片。
- 教师和管理端采用更高信息密度，学生端采用更强的单任务聚焦。
- 圆角、阴影和边框形成固定层级，避免每个模块独立发明样式。

## 10. 前端技术重构建议

### 10.1 推荐栈

- Vue 3 + TypeScript + Vite。
- Vue Router 管理角色路由和深链接。
- Pinia 管理用户、权限、学习上下文和跨页面草稿。
- TanStack Query for Vue 或统一 request 层管理缓存、重试和请求状态。
- Element Plus 只用于表单、弹窗、表格等基础交互，品牌页面和核心学习组件自定义，避免模板化外观。
- ECharts 只用于确有比较价值的趋势和分布，不把所有数字都图表化。
- Vitest + Vue Test Utils + Playwright。

### 10.2 推荐目录

```text
frontend/
├─ src/
│  ├─ apps/              student / teacher / admin 应用壳
│  ├─ router/            路由与权限守卫
│  ├─ api/               接口、SSE、错误规范
│  ├─ stores/            auth、context、draft
│  ├─ components/        通用组件
│  ├─ features/          chat、practice、mistakes、growth...
│  ├─ views/             页面
│  ├─ design-system/     tokens、typography、icons、states
│  └─ tests/
└─ public/
```

### 10.3 迁移方式

不建议一次性推倒全部功能。采用“新壳逐页替换”：

1. 建立 Vue 应用壳、设计令牌、鉴权和请求层。
2. 先迁移登录、学生首页和 AI 学伴，形成最小闭环。
3. 再迁移练习、结果和错题。
4. 最后迁移教师端和管理端。
5. 新旧页面短期共存，页面验收通过后删除旧实现。

### P0：无需新增后端即可做

- 三角色应用壳与路由。

- 教师学生列表、详情和审核工作台。
- 管理端表格、上传进度轮询和错误反馈。

- 周报/月报与家长视图。
- 班级作业闭环。
- 评测集和模型/检索版本对比。

## 12. 实施路线与排期建议

### 阶段 A：前端底座与视觉基线（1 周）

- 完成 Vue 3 工程、路由、权限、请求层、SSE 客户端。
- 建立色彩、字体、间距、圆角、阴影、图标和页面状态规范。
- 完成学生/教师/管理三套应用壳。
- 交付登录页、导航和基础组件库。

### 阶段 B：学生核心闭环（2 周）

- 今日学习首页。
- AI 学伴、会话管理和来源面板。
- 练习设置、作答、结果。
- 错题本和学习成长。
- 完成桌面端和移动端核心流程。

### 阶段 C：教师端（1.5 周）

- 教学概览、学生学情、学生详情。
- 知识点筛选、学习线索审核、教学活动。
- 导出和关键空/错状态。

### 阶段 D：管理端（1.5 周）

- 系统概览、用户管理、学习活动。
- 教材/题库上传、文档列表和任务进度。
- 检索调试迁移与质量监控基础页。

### 阶段 E：质量收口（1 周）

- 响应式、键盘操作、减少动画、对比度。
- 单元测试、关键路径 E2E、异常和弱网测试。
- 性能、资源加载、国内字体资源和浏览器兼容验证。

如果只有一名前端开发，建议总工期按 7–9 周估算；如果设计、前端和后端可以并行，P0 可压缩到约 4–5 周。

## 13. 第一版验收标准

### 产品验收

- 学生能在 3 次点击内从首页进入推荐学习任务。
- 一次完整流程可连续完成：提问 → 查看依据 → 开始练习 → 查看解析 → 错题复习。
- 教师能从概览定位学生，并在学生详情中找到对应依据和处理动作。
- 管理员能看到内容导入的真实进度和失败原因。
- 所有空状态都告诉用户下一步可以做什么。

### 技术验收

- 页面具备真实 URL，刷新后仍停留在当前页面。
- 角色权限在路由层和接口层均生效。
- API 错误、登录失效和网络中断有统一处理。
- 核心页面 Lighthouse Accessibility 目标不低于 90。
- 学生核心流程具备 Playwright E2E。
- 首屏不依赖不可控的境外字体服务。

### 视觉验收

- 三端共享品牌语言，但信息密度与交互方式符合各自角色。
- 页面不以大量同形卡片、无意义渐变和装饰性数字作为主要视觉。
- “学习路径尺”只用于关键学习流程，成为产品的识别元素。
- 颜色、排版、图标、空状态和反馈在所有页面保持一致。

## 14. 推荐立即启动的第一批任务

1. 建立 Vue 3 + TypeScript 前端目录和三角色路由壳。
2. 输出 5 个高保真关键页：首页、AI 学伴、练习作答、教师概览、管理内容导入。
3. 定义设计令牌与基础组件：按钮、输入框、选择器、卡片、表格、状态、空页面、弹窗。
4. 封装鉴权、API 请求、SSE 和全局错误处理。
5. 用现有接口打通“提问 → 练习 → 错题 → 掌握度更新”的学生闭环。

这五项完成后，再扩展教师和管理功能，能最大限度降低后续返工。
